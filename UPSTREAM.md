# Upstream

KORE Factory is a fork of [T3 Code](https://github.com/pingdotgg/t3code) (MIT). Our repository is `idevkore/kore-factory` (public).

- **Base tag:** `v0.1.9` (commit `24e77473e`). `main` and `develop` both started there.
- **Remotes:** `upstream` points at T3's repository with pushing disabled. Never push T3's tags to our repository: a pushed `v*.*.*` tag starts `release.yml` (see `docs/kore/harness-notes.md`).

## Taking a new upstream release

Merge stable tags only (skip `-nightly` tags), one at a time, into `develop` with a merge commit. Never rebase our branches onto upstream and never force-push.

```bash
git fetch upstream --tags
```

```bash
git tag -l 'v*' --sort=-v:refname | grep -v nightly | head -5
```

```bash
git switch develop
```

```bash
git merge --no-ff vX.Y.Z
```

Keep git's own message (`Merge tag 'vX.Y.Z' into develop`). Resolve conflicts this way:

- `apps/web/src/routeTree.gen.ts`: take upstream's version, then run the web dev server or build once so the plugin regenerates it with `/island`.
- `pnpm-lock.yaml`: take upstream's version, then run `pnpm install` so our three packages are added back, and commit the result.
- The files in the table above: keep upstream's change and re-apply ours on top. Update this table if a change moves or goes away.

Then install, run `vp run check:changed`, start the app once, open `/island`, and fix anything before merging `develop` into `main`.
